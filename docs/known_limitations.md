# Known Limitations and Future Improvements

## Known limitations

**Verification status of this initial build**
- The project was generated in a sandbox where `pip`/`npm` installs were blocked. The real FastAPI app, PyMuPDF extraction, ChromaDB, Sentence Transformers and Gemini calls were **never run together**. See [testing_guide.md](testing_guide.md) for exactly what was and was not executed.
- Pinned versions in `requirements.txt` / `package.json` were not install-tested. `package-lock.json` is **not included** (it can only be generated by `npm install`); generate and commit it.
- The default `GEMINI_MODEL` (`gemini-2.5-flash`) may have been renamed or retired by the time you run this; it is configurable.

**Answer quality and honesty**
- Citation checks are **structural**: they prove a cited evidence ID exists and that excerpts are real stored text. They do **not** prove the cited passage supports the sentence it is attached to.
- `MIN_RELEVANCE_SCORE=0.30` is an untuned starting value for `all-MiniLM-L6-v2`. Too low → weak matches slip through; too high → good questions are refused. Tune it with your own documents.
- No conversation memory: `session_id` is accepted but each question is answered independently, and follow-up questions ("what about the second one?") will not work.
- Only the top 5 chunks are used, so questions that need a whole-document summary or many scattered facts may be answered incompletely.
- Tables, figures, equations, footnotes and multi-column layouts may extract poorly.
- Page numbers are PDF page positions (1 = first page), not the page labels printed on the page.
- Prompt-injection text inside a PDF is mitigated only by prompt instructions, not guaranteed.

**Functionality**
- No OCR: scanned/image-only PDFs are reported as `no_text`.
- No document deletion, renaming or re-processing in the UI/API.
- No authentication, user accounts or per-user data; every visitor sees every document.
- Evaluation shows usage counts only; no accuracy, faithfulness or recall scores.

**Engineering**
- Documents and counters are stored in JSON files: not safe with multiple server processes/workers.
- Upload processing is synchronous; large PDFs keep the upload request open (and the first request loads the embedding model).
- No rate limiting, malware scanning or request-size limits beyond the PDF size check.
- Frontend has no automated tests (it was only compile-checked and render-smoke-tested; see testing guide).

## Future improvements

1. OCR for scanned PDFs (e.g. Tesseract / OCRmyPDF) with a clear "OCR used" label.
2. Semantic citation checking (entailment model or sentence-level evidence alignment).
3. Retrieval upgrades: hybrid keyword + vector search, re-ranking, query rewriting, tuned thresholds.
4. Conversation memory using `session_id`; follow-up question handling.
5. Delete/re-index documents; background processing with progress; a real database (SQLite/PostgreSQL).
6. A labelled evaluation set (question → expected page) with recall/precision and faithfulness metrics.
7. Highlight the cited passage inside an in-app PDF viewer.
8. Authentication, per-user workspaces, rate limiting, deployment (Docker), HTTPS.
9. Frontend tests (Vitest + Testing Library) and end-to-end tests (Playwright).
10. Streaming answers and better handling of tables and figures.
